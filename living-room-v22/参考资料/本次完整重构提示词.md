## 1. 最终体验与实现范围

形成五种明确不同的功能空间：

- HOME：首页为黑底家具图案场，拉绳后重排成白底超大英文与小家具交织的编辑海报。
- EXHIBITION / 展览：暂时空页面，显示“暂无 / NOTHING ON VIEW YET.”。
- PREMISE / 前提：解释客厅、起居室、关系四层和客／厅／居三维观察体系。
- DISPLAY / 展示：接近满屏的六面图像立方体内部空间，可观看、筛选、聚焦、收藏全部素材。
- RELATION / 关系：用户从空房间线稿开始布置的关系手账，可以放收藏家具、释放卡片、画画、连线、命名、分析。
- ARCHIVE / 归档：客／厅／居三层房间横向延伸，真实素材按时间挂在墙上，家具散布在地面。
- DETAIL：单件素材研究详情，能返回真实来源页面。

全站共享两种家具收藏贴纸。它们是收藏容器，可以产生多个页面实例；各实例共享内容，但位置独立。首页实例是参与文字排版的装饰；其他页面实例是可拖动的收藏便签。

不要把这次重构降格为换颜色。五个页面必须拥有不同的结构与交互。

## 2. 技术与资料保留

继续使用原生 HTML、CSS、JavaScript、系统字体、SVG。无 npm、无打包依赖、无框架、无外部在线字体。不得引入 React、Vue、Three.js、WebGL、GSAP、Lenis 或 UI 框架。

保留双击 index.html 可浏览的离线能力。素材数据继续来自本地 JS，不依赖 fetch 本地 JSON。可增加独立 JS 文件并用普通 script 标签按顺序加载；避免使用会阻止 file:// 工作的模块方案。

六面展厅使用 CSS 3D；手账背景、连线和笔迹优先使用 SVG，普通二维 Canvas 仅可作为笔迹层备选，不用于替代全部交互对象。

保留259份图片的现有唯一 assetId、图片路径、缩略图、原始路径、标题、来源、年代、地区、关系说明、分类和待核对标记。实施前记录数据总量、ID与路径清单；结束后对比。不要重新编号，不把不同作品合并，不随机重分标签，不虚构缺失作品信息。

原有分类是建议分类的，继续保留这种状态。现有数据中的 `classificationNote`、`mappingNote`、`originalPath` 不能丢失。未知信息标“待补充”，不要把关键词推定写成已确认事实。

全站文本显示统一使用 textContent 或严格转义，尤其是用户自定义名称、备注、线段名称与导入数据。

## 3. 路由与三套概念分离

新路由至少包括：
`#home`、`#exhibition`、`#premise`、`#display`、`#relation`、`#archive`、`#detail?id=A001`。

网站页面、素材来源、关系分类是三套独立系统：

1. 页面决定使用方式：看概念、看图、构建关系、查归档。
2. sourceGroup 决定原始来源：A 经典艺术档案、B 文学意象、C 社会素材、D 形式灵感、O 其他灵感。
3. layer / guest / hall / self 等字段用于解释、筛选和分析素材。

废除 A＝ARCHIVE、B＝PREMISE、C＝RELATION、D＝DISPLAY、O＝EXHIBITION 的硬绑定。旧 section 字段如需保留，可迁移为 legacySection，不能继续作为页面素材池的唯一过滤条件。DISPLAY 和 ARCHIVE 默认都读取全部 ASSETS。

旧 `#room?section=...` 链接应通过 replaceState 兼容到对应新页面，不产生反复后退的循环。

详情入口记录 originRoute、originState 和必要的滚动位置。从归档、展厅、收藏环、关系画布、RELATED 进入详情后，返回真正来源。连续浏览 RELATED 时保留最初来源；直接打开详情链接且没有来源状态时回 DISPLAY。不能无条件 history.back() 导致退出网站。

## 4. 全站色彩和视觉边界

采用一套克制的粉绿主方案：

- 深色首页：#171717。
- 白色首页及大部分阅读背景：#FFFFFF。
- 主要文字与轮廓：#111111。
- 主粉：#F26BAA。
- 辅绿：#A9C85A。
- 空间辅助浅色：可用以上颜色加白调浅。

如选择粉蓝替代方案，将辅绿统一替换为 #AFCBDE；不要每个页面随机换方案，也不要同时让粉、绿、蓝三种颜色占大面积。

粉棕黄旧主色退出界面。黑白灰不计入两种强调色。真实档案照片保持原色，不套滤镜强行统一；限制的是界面、家具插画和空间装饰。

首页采用纯白，不以大面积米黄代替。手账和长廊允许极浅中性色。可以用原家具 SVG 延展少量不规则轮廓，轻微手绘感集中在家具本身，禁止高噪点纹理影响阅读。

全站不使用商业模板、卡片面板堆叠、复杂导航、霓虹、全屏玻璃拟态。图1式预览的薄线信息框、真实档案挂画细边与手账线条是局部例外。

中文内容保持清晰。重要说明不低于16px；常用标签尽量不低于14px。超大英文只承担首页视觉和页面标题，不能让整个理论页面变成难以阅读的大字墙。

## 5. HOME：首次黑底，拉绳变白并真正重排

保留明显的几何屋顶与屋檐拉绳；导航缩小，不做复杂矩形导航栏。首页理论长文移到 PREMISE。

首次访问且没有当前会话状态时，默认 DARK：近黑背景，仅家具图案作为主体，没有大字流；左侧贴纸工具暂不显示。顶部必要的导航和拉绳提示可存在。离开再返回首页恢复当前会话的拉绳状态；新会话默认黑底。

保留约8–12个导航家具，五个页面至少各有一个清晰入口，不再使用20个近似重复入口。导航家具与收藏贴纸在数据类型和事件上分开。

点击或下拉拉绳20–35px：切换到 POSTER。背景变纯白，家具在新色板内换色，超大黑色章节标题进入家具之间，家具大小和位置一起重排。再拉一次恢复 DARK。

拉绳使用 pointer capture，支持点击、拖动、Enter、Space；同一手势只能切换一次。pointercancel 清理状态。快速连续操作不产生残留动画或重复事件。

## 6. POSTER：大字与小家具同一文字流

这是首要视觉要求：标题不能绝对定位叠在家具上。删除当前 `.furniture .section-word` 的 absolute + z-index 覆盖方式。

把大字、导航家具、用户插入的装饰贴纸都做成同一 editorial flow 中独立占位的 token。文字和图片拥有真实宽高与间距，排版主动为彼此让位。不要把图片当文字背景、用标题覆盖图片，也不要把标题做成家具下方的小卡片说明。

核心英文只使用 EXHIBITION、PREMISE、DISPLAY、RELATION、ARCHIVE。它们是对应入口的章节标题，不是长篇装饰口号；图形附近标题必须匹配实际跳转。

桌面英文约 clamp(64px, 9vw, 150px)，粗无衬线，字重800–900，紧行距约0.90–0.98。不能因负字距把字母挤叠。移动端单独减小字号，保证 EXHIBITION 之类长词不会横向溢出；不要用随意断词破坏英文。

家具常规视觉高度32–70px，少数强调家具可到90–110px，整体明显小于文字。任何单个家具和贴纸的总占位不得超过当前两行文字高度。布局允许轻微上下错位和±5°旋转，但不侵入相邻文字实际边界。

每行长短不同，疏密不同，有的行只放一个标题，有的行插入两个家具。使用经过设计的 token 序列和稳定的错位值；不要每次渲染重新随机打散。桌面至少保留约30%留白。不能排成等宽宫格或整齐居中的列表。

用户提到的头像、小物件和图标用于描述“图像是文字的一部分”这种构成方式；此项目核心仍是家具，不擅自加入无关人物头像填空。

DARK→POSTER 可用 FLIP：保留 token 的稳定ID，读取旧边界，切换布局，读取新边界，用逆变换过渡到新位置。900–1100ms，无弹跳。缩放/旋转外层与家具内部动画分层，避免互相覆盖 transform。媒体断点变化时重新计算，不能复用过期坐标。

## 7. 两种家具贴纸的明确功能

本次固定两种，不做庞大贴纸商店。以下为可执行默认设计，可更换图形但不要丢失角色区别：

- SOFA / 收集沙发：快速收集值得保留的素材，主要用于汇集与顺序浏览。
- CABINET / 对照柜：挑选用于比较的素材，展开后可选两张进行字段对照，并可把这一组带入 RELATION 分析。

两者都是收藏容器，均可接收、删除、转存和打开素材；“功能不同”体现在收集与对照，不是让第二个完全无法收藏。纯装饰是它们在 HOME 上的情境行为，不是第二种贴纸在全站的唯一功能。

每种家具对应稳定 folderId，所有同款实例指向该ID；不是根据图片文件名猜共享关系。用户修改名字不会更换身份。

名称可改，但 SOFA/CABINET 的小型类型提示仍可用于理解功能。不得根据“沙发”强制把收藏判为亲密层；容器用途与素材关系层独立。

## 8. 左侧贴纸栏与首页插入

桌面左侧竖列，距边缘8–18px，默认家具图形宽约28–38px；交互热区至少44px，避免难点中。hover/focus 或点击展开时图形放大到约70–90px，不推动页面布局。名称在下方，不能小到看不清。

首页 DARK 隐藏此栏；拉绳到 POSTER 时与文字流一起出现。其他功能页始终可用。切回 DARK 时暂存首页贴纸位置但隐藏，重新 POSTER 后恢复。

从左栏拖出是在目标页创建一个实例，原件永远留在栏中。拖拽幽灵用于反馈；失败松手不创建实例。

HOME 接收贴纸的方式是 token 插入：根据指针位置给出“插入到这两个 token 之间”的提示，松手后参与文档流，文字和家具重新让位。不使用 absolute 盖在字上。首页实例只做轻微悬浮旋转装饰，不打开收藏环，不进入章节、不展开分析。再次拖动可以换插入位置。需要删除时用小型编辑操作移除此实例，不删除收藏夹数据。

首页导航家具继续跳转；收藏家具不能误触发导航。相同家具轮廓若用于两种角色，应通过位置、名称和小型收藏数量提示区分，不让用户猜。

## 9. 页面实例、坐标和同步

非HOME页面贴纸为覆盖式便签，不改变正文、展墙、照片长廊的排版。可拖动调整位置，点击展开；左栏原件不动。

数据至少分为：

- collections：folderId、type、name、hasBeenNamed、assetIds、comparisonSelection。
- instances：instanceId、folderId、routeKey、coordinateSpace、position、expanded。
- homeTokens：导航字/图token与首页贴纸实例的顺序。
- relationBoard：节点、边、笔迹、文字、相机平移和缩放等。

普通页面浮贴纸保存为可视区域归一化位置，窗口变化时限制在可访问范围；RELATION 保存世界坐标，跟随画布平移缩放；HOME 保存 token 顺序。三种坐标不可混用。

DETAIL 位置可按 `detail:assetId` 保存，避免把所有不同详情误当一张画布。

同一 folder 的收藏内容和名字全站立即同步，不在每个实例里拷贝独立 assetIds。对照选择也按 folder 管理。实例位置、大小、展开状态不必同步。

同一页可以有多个同款实例，彼此位置独立、内容共享。移除一个实例只移除摆放，不删除 folder 和其他页面的实例。

## 10. 收藏、转存、删除、展开和命名

DISPLAY、ARCHIVE、DETAIL、RELATED、关系画布中的真实素材均可收藏到两个家具容器。卡片拖入左栏或页面实例都有效；目标高亮，成功显示轻量反馈。

同一个 assetId 在同一收藏夹只保留一次；可同时存在于两个收藏夹。拖拽数据用 `assetId` 与来源上下文，不依赖 DOM索引或当前图片src。

从收藏夹A拖到收藏夹B默认“复制收藏”，保留A；按 Shift 拖动或小菜单“移动到”才从A移除，并显示反馈。触屏提供复制/移动菜单。相互转存仅针对卡片，不允许把整个文件夹收藏进另一个文件夹形成循环。

点击非首页家具：家具放大，卡片在附近小弧形/环形展开，卡片为平面缩略图60–100px。优先在左侧展开；若靠左边界，则自动向右侧展开，优先保证所有内容在屏幕内。必要时上下翻转、缩小半径或分页，不能把内容裁掉。

环绕范围约120–180px，每页最多6–8张，不把几十张挤在一个圆环里。卡片可缓慢小角度漂动，不翻转背面、不高速绕转；鼠标或键盘进入整个收藏环立即停止，便于点中。减少动态效果设置下为静止弧形。小屏以可滚动展开带替代圆环。

卡片主体点击进入原素材详情；左上角×只从当前收藏夹移除。阻止×的 pointerdown、click 冒泡，不能删除时误打开详情或开始拖动。删除收藏不删 ASSETS、磁盘图片或另一收藏夹的同一图片。提供撤销一次操作的机会。

名称最初显示“收集沙发”或“对照柜”。尚未命名时单击名称编辑；首次保存后，只有双击名称或键盘编辑操作才重命名。移动端提供菜单替代双击。Enter保存、Escape取消、失焦保存非空合法内容；空名恢复原名，长度约24个中文字符上限。名字变更立即出现在所有实例及相关分析中。

收藏环、菜单、名称编辑框与鼠标之间的过渡不能自动关闭；使用联合悬浮区域和短暂关闭延迟。不要因点击编辑名字而打开/折叠收藏夹。

## 11. DISPLAY：六面空间与遮挡问题

彻底删除中央 `.island-shell`、档案中岛、自转、中岛背面和卫星图。展厅中央保持空，只有进入主动聚焦预览时可以在屏幕前景展示选中图。

创建真正立方体内侧的 FRONT/BACK/LEFT/RIGHT/TOP/BOTTOM 六个正方形面；六面均分布素材卡片。TOP/BOTTOM 是可通过向上/向下观看抵达的真实面，不是背景装饰。

相机位于立方体内部靠中心位置，使用一致的坐标约定。根据面朝向校验内侧法线、rotateX/rotateY顺序、translateZ正负号及 backface-visibility。不能盲目复制旧变换再增加两面。

所有 slot 均约束在其正方形面的内部，卡片尺寸、间距和轻微旋转计算后也不能越过面边缘。卡片只沿面内方向排布，不穿过房间中心。给面上图像很小的内偏移避免共面闪烁，不能用大 translateZ 把卡片送到镜头前。

排查旧版 transform-style 被祖先的 opacity/filter/overflow 扁平化、背面面板遮挡、超大透明命中区域、3D stacking context 与前景预览混用等风险。背向或不应可见的面不能截获当前可见卡片的点击。不要用不断加大 z-index 当作3D遮挡的修复。

CSS 3D 没有 WebGL 式 near 参数可直接设置；通过合理面距、投影距离、相机位置和正确几何防止穿镜。必须在全部六个面及面交界角度实际验证。

场景坐标和屏幕层分离：滤镜抽屉、收藏工具、拖拽幽灵、聚焦预览统一挂在不受3D变换的顶层容器。需要弱化背景时优先用屏幕白色遮罩，不随意把 preserve-3d 的祖先设为低 opacity。

## 12. DISPLAY：无自动巡航的鼠标视角

移除旧 tick() 中按时间自动累加 yaw 的逻辑和 PLAY/PAUSE巡航按钮。没有用户控制意图时场景不自行转动。

桌面默认采用边缘控制：鼠标在场景中央的死区内相机静止，越靠左右边缘水平转速越大，越靠上下边缘俯仰速度越大。仅在真实场景区域计算归一化坐标，不用包含顶栏的整个窗口坐标。

yaw 可连续360°；pitch限制约±80°避免倒置，同时提供 F/R/B/L/TOP/BOTTOM 的低调方向快捷键/按钮，保证顶面底面确实可达。相机速度建议上限水平15–25°/秒、垂直10–18°/秒，可根据实测调整。

鼠标停止在边缘代表继续查看该方向的操作意图；进入中央死区、移出场景或离开窗口立即停止。另保留“固定视角／鼠标视角”切换供需要稳定观看的人使用，不恢复无人操作的巡航。

hover卡片、聚焦预览、拖素材、拖家具、筛选抽屉开启、收藏环展开、输入框编辑和页面不可见时，都暂停相机。暂停时清零角速度，恢复时不补算暂停时间、不突然甩动。

不能用“相机先动、卡片在鼠标下不断换hover”的循环。优先检测真实鼠标进入目标，设置聚焦锁，保留最后稳定视角；离开联合预览区域后延迟约200ms释放。

手机使用触摸拖动视角，横向与竖向均可；不靠hover，不自动旋转。提供方向按钮保障完整访问。拖卡片收藏与拖空白旋转必须被独立识别。

## 13. DISPLAY：六面换图与稳定锁定

保留全部素材池，但同时可见DOM只占一部分。例如桌面六面合计72–144个slot、移动端36–72个，实际按性能和密度调节，不做259×6张高清图。

所有六面均有图片；素材不足时允许重复显示真实 assetId，集合统计按唯一ID去重。没有筛选结果时显示明确空状态，不用旧图片伪装还有结果。

每6–10秒最多选择约5%–10%的非锁定slot做渐变交换。位置交换通过稳定slot交换assetId实现，图像淡出、预解码下一图、切换、淡入；几何体不飞穿房间。固定布局和seed用于重现密度状态，动态换图只改变内容。

锁定条件包括 hover、keyboard focus、聚焦预览、拖拽源、尚未完成的图片解码/交换事务。用户中途指向正淡出的图片时，立即取消该事务并恢复当前稳定图片；不得先显示A标题再切成B。

聚焦期间暂停整批交换最稳妥；退出再恢复。换图定时器只有一个，页面隐藏时暂停；路由离开后清除。慢网或解码失败保留旧图，不闪空白。

GRID 保留1–7：左端大且疏，右端小且密。根据实际占位重新计算容量，显示真实可见数量。密度重排不能导致卡片越界；操作密度时退出或稳定保留聚焦，规则全程一致。

## 14. DISPLAY：图1式聚焦预览

桌面 hover 稳定约150ms后进入聚焦；立即冻结当前slot和相机，不跳转URL。

在独立屏幕前景层呈现：左侧/中央完整大图，右侧薄线资料面板，左右极简切换箭头，周围大量白。背景六面仍隐约存在，被白色遮罩弱化。

图像使用 object-fit:contain，约260–420px或适配窗口的更大尺寸。真实画作保留完整矩形，不把画作扣成不真实物体；只有原本带透明背景的家具图才保留自然外轮廓。

面板只显示：标题、年代、地区、来源、主关系层、客／厅／居、短说明、查看详情、收藏。没有价格、购物车、数量、商品品牌。可选很轻的粉色氛围，但不增加科技玻璃效果。

原卡片、放大图、信息框、切换箭头及其间可移动区域组成同一个聚焦会话。用共享的 previewAssetId 和明确关闭状态维护，不把预览开关简单绑在原卡片的 mouseleave 上，否则移向信息框就会消失。

左右箭头浏览当前筛选集合，仍停留DISPLAY且URL不变；对应资料与收藏ID随选中项一起更新。原slot保持锁定直到会话结束。点击大图或“查看详情”才导航；点击“收藏”不导航。

从聚焦图拖往收藏家具时维持预览与素材身份；松手后决定保留或退出，不能在拖途中恢复相机。Escape、关闭按钮或点击空白退出；退出后的指针需离开原触发目标才再次开启，防止反复弹出。

手机轻点一次打开预览，使用明确“查看详情”进入详情，不能依赖必须精准重复点同一点。键盘focus也可打开，Escape可关闭。

## 15. DISPLAY：折叠筛选与整屏空间

默认顶部仅48–56px的简洁工具条：返回、DISPLAY / 展示、FILTERS、已选条件数量及必要的查看模式入口。取消展厅上方巨大章节标题和四排常驻标签。

场景高度为 `100dvh - 顶栏实际高度 - 安全区`，不因筛选面板展开而缩小。GRID在一角，家具栏在左侧，都不永久遮住主要内容。

FILTERS 是浮层抽屉：桌面不超过约30vh，可内部滚动；手机可更高但能明确关闭，仍不挤压场景。开启即暂停相机。关闭恢复同一角度、相同筛选和密度。

保留主层单选、客主项单选、居主项单选，厅/感知/审美多选；不同维度AND，多选厅要求同时包含全部所选标签。点击已选取消，支持清空、结果计数、空结果恢复。来源组A/B/C/D/O作为独立可选来源筛选，不能替代关系层。

## 16. PREMISE：按图2讲清概念

以清晰研究图谱呈现，避免一整页论文。内容依序展开：

1. 客厅的狭义含义：会客厅堂，强调他者进入、接待与主客礼仪。
2. 起居室的广义使用：日常生活、休息、共同使用、身体感受和物的使用。
3. 项目综合理解：同一个空间兼具对外会客与对内起居，“客／厅／居”是本项目的分析拆分，不是声称该词有这种语言学词源。
4. 核心句：“居者借助厅中的空间与物，与客或其他居者发生关系。”
5. 关系四层借鉴距离结构，不照搬固定米数；“亲密／共用／礼仪／边界”是项目转译，不说成 Hall 原理论的四个原名。
6. 客／厅／居是三个同时存在的观察位置，不是三个先后阶段。

用矩阵呈现主导对应：

| 主关系层 | 客：人与他人 | 厅：人与物 | 居：人与自己 |
|---|---|---|---|
| 亲密 INTIMATE | KIN 亲属关系 | FURNITURE 家具 | BODY 身体 |
| 共用 SHARED | COMPANION 友伴关系 | DAILY_OBJECT 日用物 | HABIT 习惯 |
| 礼仪 RITUAL | HOST_GUEST 主客关系 | HOSPITALITY_OBJECT 待客物 | ROLE 角色 |
| 边界 BOUNDARY | STRANGER 陌生关系 | DISPLAY_OBJECT 展示物 | SELF_BOUNDARY 边界 |

明确“这只是主导对应，不是强制绑定”。沙发不自动等于亲密，茶具不自动等于礼仪。根据素材实际讨论判断。

参考图2中列出的词典和 Edward T. Hall《The Hidden Dimension》(1966)可作为待核对出处线索；如写逐字引用或具体链接，实施时核实原文，不虚构页码。页面区分资料原文、项目解释和建议分类。

视觉借图2层级，不照搬所有圆角面板；使用留白、短段、细连线和一张清晰矩阵。以粉绿或粉蓝强调关系，颜色不是唯一识别方式。

## 18. RELATION：空白透视房间手账

RELATION同时承担收藏分析页面，不再增加第六个平级导航。分析以本页侧栏和收藏容器的分析入口呈现。

首次打开时只有淡色房间线稿、左侧家具栏和底部工具。没有预先放好的卡片、家具、线段和示例笔迹。之后回到已有手账应恢复保存内容，不能每次清空。

背景为室内向前看：正面墙、少量左右墙、地板，透视线淡而克制，像可书写的建筑草图。不是格子背景填满的仪表盘，也不是复杂真实3D房间。

采用二维可平移缩放的世界坐标工作区叠在透视底图上；卡片、家具、线条保持易读，不因装饰透视变得难点。支持比视口大的连续工作区、缩放与回到内容范围。固定左栏与工具条不随画布缩放。

从左栏拖入家具实例，松手位置必须通过屏幕→画布逆变换计算；缩放/平移后不能出现落点偏移。

点击家具展开收藏环。环内卡片可单独拖出成为board asset node。节点记录assetId与来源folderId，不复制整份素材metadata。同一素材可有多个摆放节点，但分析默认按assetId去重。

删除一个自由卡片节点仅删除摆放；删除收藏环内的×才取消对应folder收藏。自由节点被移出收藏夹后仍可保留，但显示“已不在来源收藏夹”状态，避免静默丢掉手账。

## 19. 自动关联：有依据，不乱连

只对用户已摆入画布的节点计算关联，不给整个素材库生成毛线团。自动关系是建议，不是历史因果或作者意图的证明。

卡片用现有metadata；家具用其收藏内容的汇总。空收藏夹不自动连线。相同folderId的两个实例表示同一内容，不凭完全相同数据制造“发现”。

可用明确、可解释的默认评分：同一主层+3；相同客主项+2；相同居主项+2；厅标签有交集+1；感知交集+1；审美交集+1。阈值例如≥5，并要求至少两个独立维度命中。因数据存在主导对应，不把互相推定的字段装成多个独立证据；界面保留建议分类提示。

“都包含家具”“都属于视觉”之类宽泛标签不能单独触发连线。相同ID可显示“共享N份素材”，但不要自动归纳成相同主题。时间接近只作辅助说明，不单独判断关联。

收藏夹间比较用去重后的素材集合及标签分布，不仅用标签并集造成假相似。显示共有素材数、各自独有数、主要共同字段、主要不同字段。可用Jaccard等透明计算，但只展示用户能理解的证据。

自动线采用细虚线，每节点最多显示最强的约3条，剩余在分析里查看，防止全互连。hover线显示具体命中字段和相关素材，不能只写“相关”。

自动线删除后保存抑制键，包含两个稳定实体ID和规则版本；拖动节点、刷新、重算不能马上复活。提供“恢复被隐藏建议”才能恢复。自动重算不得覆盖用户手动线或命名。

## 20. 手账工具：选择、铅笔、钢笔、荧光笔

底部工具条简洁：选择/移动、铅笔、钢笔、荧光笔；补充小型撤销/重做。工具状态有清楚选中反馈。

选择模式：拖家具和卡片、点开内容；空白拖动平移或按住Space临时平移。没有绘图时笔迹层pointer-events:none，不能盖住全部点击。

铅笔：自由书写与绘画，细线，记录世界坐标路径。不做假手写识别。若需要可检索文字，可使用轻量文字便签，不将自由笔迹冒充识别后的文字。

荧光笔：宽而半透明，位于内容下方，标记不挡点击。一次笔画透明度合成稳定，不能每个采样点叠加成一条黑块。

绘图工具激活时，只在空白画布接收画笔；节点、名字、卡片按钮和工具条保留明确命中优先级。笔画从空白开始后capture该指针至结束，即使途中经过节点也不会误点；在节点上开始拖动则不生成笔画。鼠标进入工具条不会画线。该规则满足“可以画，但不破坏其他交互”。

钢笔是关系连接工具：先选起点再选终点，显示预览线，Escape取消；支持家具↔家具、家具↔卡片、卡片↔卡片。

还要支持用户说的“连接它们之间的线段”：钢笔命中已有线时创建明确junction节点，保存edgeId与沿线参数t；允许节点↔junction、junction↔junction，不把命中位置只存成屏幕坐标。避免循环依赖；删除承载线时，把其junction转为当前位置的自由锚点，连接到锚点的其他线保留。

新建手动关系后可立即输入名称，Enter保存、Escape取消输入但保留未命名线。双击线标签改名。家具名称使用全站命名规则。

节点移动、缩放、重排时线端点同步更新。通过坐标计算更新SVG path，不依赖偶然的DOM布局。手绘笔迹不自动附着到移动节点；连接线才附着。

## 21. 连线删除、选择与输入互不冲突

关系线的可见线宽约1px，但透明命中路径可宽8–12px。空白处pointer-events:none，只有path stroke可命中，不能一个全屏SVG挡住画布。

hover线高亮并出现小型删除操作；悬浮后按Delete/Backspace可删除当前指向的线，或先选中再删除。键盘删除优先级明确：正在编辑输入框时只编辑文字，不能删图；没有有效选中/悬浮对象时不做破坏性操作。

删除线不删除端点；删除节点仅处理附着于这个节点的边，能撤销。不能把全局Delete绑定成“删除最后一条线”。

提供有边界的undo/redo：节点新增/移动、收藏加入/移除、命名、绘图、线条创建/删除均能撤销关键操作。长拖动和一整条笔画各记作一次操作，不为每个pointermove产生历史记录。

## 22. ANALYSIS：对收藏的可核对分析

关系页可折叠分析栏，关闭时不占工作区。默认分析当前画布中放入的folder及自由卡片，另可切换选中的某个folder；不能把未放入画布的所有收藏偷偷并进分母。

将folder里的内容与自由卡片合并，按assetId去重；同时注明“容器数量、独立素材数、摆放实例数”区别。同一素材在两个folder或三个节点出现，不算三份作品。

输出至少包括：主关系层分布、客/厅/居高频字段、感知与审美共有标签、年代覆盖与未知比例、组间共同素材与差异、可继续追问的问题。

示例句式只是模板，数字必须实时计算：“两个收藏夹共包含N份独立素材，其中M份为礼仪层；两组都出现家具标签，但客关系的主要分布不同。”每一项可查看贡献该结果的真实素材。

缺失字段不当成同一种共同标签；标明未知/待核对比例。现有metadata由规则推定的，分析结果需注明“基于当前建议分类”。不从“同为蓝色”推导同一艺术史流派，不从主客标签推导未经资料支持的权力故事。

不接外部AI也能完成，使用实际字段和规则即可。没有素材时提示先放入收藏家具；只有一份素材时给单件结构，不能声称发现组间规律。

## 23. ARCHIVE：三层长廊，纵向客厅居、横向时间

按图3建立上下三层彼此对应的长房间。上层 GUEST / 客，中层 HALL / 厅，下层 SELF / 居。“局”为输入误写，统一使用“居”。

每层有挂画的墙面和克制的地面区域，用简单侧墙和地板线形成房间感。三层共享同一横向时间坐标，时间刻度对齐，不做三条各自滚动、互相错位的长廊。

桌面尽量能同时看出三层结构；可以通过画廊容器内部横向滚动、触控板、底部时间导航或拖动空白前进。小屏可纵向查看三层，但保留同一时间位置与当前层标签。body不产生意外横向滚动；有意的长廊滚动限制在专用容器。

每份素材同时可能属于客、厅、居三个观察维度。因此同一assetId可在三个楼层各出现一次，对应楼层显示不同字段。不是把259份素材硬拆成三组，也不是复制出新的素材身份。

客层展示其guest关系；厅层展示其hall物件标签；居层展示其self状态。多选厅标签不导致同一层重复挂同一图片。字段缺失时放在该层“待标注”位置，不能默默漏掉素材。

## 24. 时间轴：真实年代、区间与未知

保留原始year字符串，另生成dateStart、dateEnd、datePrecision、dateStatus和显示标签。整数年、区间、约数、年代段分别解析，不把 parseInt 的结果当成全部年代事实。

明确作品年代、文学文本年代、资料报道年代和图片拍摄年代不一定相同；当前横轴默认使用资料表中的记录年代，提供说明，不把它们伪装成同一种拍摄时间。

“约1662–65”若经可靠解析，可扩展为约1662–1665并保持约数标记；不能确定的留“年代待核对”。朝代、无数字年代不能自行杜撰具体年份。未知时间在独立UNDATED区域，不放成0年或当前年份。

先查看现有数据的实际年代范围，不硬编码1950起点排除早期艺术作品。时间横轴必须单调且三层一致；默认可用标注清楚的分段时间带，避免早期几百年空白和当代拥挤。若分段并非等比例，明确“分段时间轴，非等比例”。不能视觉上假装等间隔就代表等时长。

同年多图通过局部多行/小组排布解决拥挤，不把横向乱移当成改年代。保留与年份锚点的关联。不要为排版随意修改源数据。

按当前可视时间窗加缓冲范围虚拟化图片，避免259×3张高清图同时解码。缩略图用于长廊，详情才加载大图。可统计259份独立素材与各层实际挂画数。

## 25. 长廊家具与照片墙

真实图片像家中照片/档案挂画，尺寸有节制的变化、轻微高低差，可用极细框，不做统一商品卡片和大段标题栏。保留可访问标题，hover/focus显示简要资料，点击进详情，拖动进收藏夹。

每层地面散布少量家具插画：沙发、凳子、边桌、书架、屏风、落地灯、柜体等。可延展现有SVG家具系统，增加不同轮廓丰富空间；不复制图3满地人物和奇异雕塑。

地面家具纯装饰，pointer-events:none、aria-hidden=true，没有hover放大或手型指针，不可收藏、不可导航。通过不显示名字/数量/交互反馈，与可移动的收藏家具清楚区分。

装饰家具只位于地面，照片只挂在墙面；不互相遮挡。插画使用统一粉绿或粉蓝体系，真实照片不改色。

## 27. 统一交互状态机，避免手势打架

统一管理 activeInteraction，不让相机、收藏拖拽、页面滚动、手写各自争夺同一个pointer。

至少区分 idle、cameraLook、assetDrag、folderCloneDrag、instanceMove、boardPan、pencilStroke、highlighterStroke、edgeConnect、nameEdit、focusPreview。

优先级：输入编辑/弹层 → 删除及明确按钮 → 正在进行的捕获手势 → 节点/素材拖动 → 当前绘图工具 → 空白画布平移或展厅相机。

按下卡片移动超过约6–8px才开始拖动，小范围移动后抬起视为点击。拖动结束必须取消该次click，不能松手就跳详情。图像原生drag和文本选区在自定义拖动中禁用，不影响普通文字阅读。

使用 Pointer Events 与capture；pointercancel、窗口失焦、页面隐藏、Escape、路由切换均能结束当前手势，移除幽灵和锁定状态。

拖拽物不是相机操作；拖空白才允许手机相机或手账平移。名称文字不是拖动把手。拖动过程中暂停hover聚焦切换、换图、轨道漂动。

不要使用整页pointer-events:none冻结界面，避免连关闭按钮和收藏目标也失效。

## 28. 数据持久化、迁移与隐私范围

收藏和手账属于当前使用者的本地数据，不把任何访问者的收藏默认上传为全站共享内容。

同一浏览器、同一站点中的页面实例实时共享一个状态源；刷新后恢复。跨设备或不同访问者不自动同步，界面不能宣称云同步。在线域名和本地file://是不同存储环境，也不要承诺两者自动共享。

结构化少量状态可用localStorage；笔迹量较大优先IndexedDB。以schemaVersion做迁移，既有sessionStorage浏览状态要兼容，不能为了升级清空有效数据。存assetId引用，不把全部图片Base64塞进存储。

用节流保存与事务/错误处理，操作提交后再写，不每帧序列化整张画布。存储不可用或超额时仍可操作当前会话，但明确告知未持久保存。提供手账/收藏JSON导出与导入作备份；导入校验版本、类型、引用ID和长度，不能把导入文字当HTML执行。未知assetId保留可识别的缺失引用，不导致整个导入崩溃。

同站多个标签页可通过storage事件或BroadcastChannel同步收藏与命名，画布位置避免相互覆盖；明确修订号及冲突策略。不要把“跨页面同步”仅实现成刷新后重新读取。

## 29. 动画、性能和生命周期

所有页面有mount/unmount或等价清理机制。路由离开取消rAF、换图计时器、监听器、Observer、未完成的预览延迟与解码回调。异步回调检查routeGeneration，禁止旧页面解码结束后更新新页面。

reduce-motion下：首页即时或短淡入换布局；六面不自动换图；收藏环静止；用户主动控制仍可用。页面隐藏时停止无意义动画。移动端避免持续高频运行不可见空间。

层级统一：场景与画布内容 → 页面实例 → 聚焦预览 → 左栏/收藏环 →筛选及工具→编辑弹层/拖拽幽灵。具体值集中定义。拖拽幽灵pointer-events:none。不要让DOM层级规则替代3D几何修复。

布局读取和写入分帧批量进行，避免大量卡片逐个强制回流；同一帧仅一次相机更新。所有可操作图片有alt，装饰家具不进入Tab序列。
